# Quickstart Copilot 総合改善提案レポート：BtoBツール案内役への進化

## 1. エグゼクティブサマリ

本レポートは、Quickstart Copilotを「バイブコーディングのセットアップ自動化」から「kintone等BtoBツールの案内役（軽量DAP）」へピボットさせるための、技術・UI/UX・ビジネスの全方位的な改善提案です。

既存のエンタープライズDAP（WalkMe、テックタッチ等）が「SaaS提供企業」や「大企業情シス」向けであるのに対し、Quickstart Copilotは**「エンドユーザーが自発的に導入できるChrome拡張」**という独自のポジションを確立します。この戦略を実現するため、現在のDOMアプローチを維持しつつ、AIモデルの最適化と「セカンドカーソル」UIの導入を推奨します。

## 2. ビジネス・ポジショニング戦略の改善

### 2.1. ターゲット市場の再定義
現在の「バイブコーダー」から、以下の「スモール〜ミドル層のBtoBツールユーザー」へターゲットを移行します。

| ターゲット層 | 抱えるペインポイント | Quickstart Copilotの提供価値 |
|---|---|---|
| **kintone導入企業の現場リーダー** | 独自カスタマイズした画面を新人に教えるのが手間 | 拡張機能を入れるだけで、自社専用の操作ガイドが動く |
| **Lステップ構築代行業者** | 納品後のクライアントからの「操作方法がわからない」という質問対応 | 納品物と一緒にQuickstart Copilotのレシピを渡してサポート工数削減 |
| **Chatwork/Slackの非ITユーザー** | 基本的な機能（タスク追加、グループ作成）すら迷う | AIが画面上で直接クリック場所を教えてくれる |

### 2.2. 競合との差別化ポイント
WalkMeやテックタッチは導入に数百万円かかり、SaaS側のコード改修（スニペット埋め込み）が必要です [1] [2]。Quickstart Copilotは**「Chrome拡張を入れるだけ」「月額数千円〜」**という圧倒的な手軽さで、既存DAPが拾えない市場を開拓します。

## 3. 技術アーキテクチャの改善

### 3.1. AIモデル戦略：コストと精度の最適化
スモールビジネスとしてスケールさせるため、LLMのコスト最適化が最重要課題です。セルフホスティングは初期段階ではコスト割れするため（月額$3,000超）、API利用を継続します。

1. **初期フェーズ（無料〜低コスト）**: **Gemini 2.5 Flash-Lite** または **Gemini 2.0 Flash**
   - Google AI Studioの無料枠を活用し、実質無料で運用。構造化出力（JSON）が安定しており、DOM解析に十分な性能を持ちます。
2. **成長フェーズ（課金開始後）**: **DeepSeek V3.2**
   - 1Mトークンあたり$0.14と圧倒的に安く、キャッシュヒット時は$0.014まで下がります。GPT-4クラスの推論能力を持ちながらコストは1/10以下です。
3. **フォールバック機構**:
   - 基本は安いモデルで処理し、エラー発生時のみGPT-4o-mini等にフォールバックするルーティングを実装します。

### 3.2. Vision vs DOM：DOMアプローチの強化
調査の結果、スクリーンショットをAIに読ませるVisionアプローチは、DOMアプローチに比べて**トークン消費が45倍高く**、スモールビジネスには不向きであることが判明しました [3]。現在のDOMアプローチを維持し、以下の強化を行います。

* **DOM圧縮（Smart DOM Tree）**: ページ全体のHTMLではなく、インタラクティブ要素（ボタン、リンク、入力欄）のみを抽出してLLMに渡します。これによりトークン消費を50〜80%削減できます。
* **セレクタのキャッシュ機構（Stagehand方式）**: 一度成功した操作（例：「保存」ボタンのCSSセレクタ）をローカルにキャッシュします。2回目以降はLLMを呼び出さず、キャッシュされたセレクタで直接操作を実行することで、APIコストをゼロに近づけます [4]。

## 4. UI/UXの改善：安心感と「案内されている感」の演出

### 4.1. 「セカンドカーソル」UIの導入（最重要）
YC採択のLayup（Whatfixが買収）が高く評価された最大の理由は、**「画面上にAIの仮想カーソルが現れ、次にクリックすべき場所を指し示す」**というUIです [5]。

* **現状**: バックグラウンドで勝手に画面が遷移し、サイドパネルに文字で進捗が出るだけ（ユーザーは「乗っ取られている」と感じやすい）。
* **改善案**: 画面上に目立つ色の「AIカーソル」を描画し、それが目的のボタンまでスーッと移動してからクリックエフェクトを出す。これにより「隣に座って教えてもらっている」体験を作ります。

### 4.2. 「自動実行」と「ステップ・バイ・ステップ案内」の切り替え
ユーザーの習熟度に合わせてモードを選べるようにします。

1. **Do it for me（自動実行モード）**: 既存の機能。AIが最後まで自動で操作する。
2. **Guide me（案内モード）**: AIカーソルが「ここをクリックしてください」と指し示し、ユーザー自身がクリックするのを待つ。学習目的のユーザーに最適です。

### 4.3. レシピ作成（録画）機能の追加
HowdyGoのように、ユーザー自身が「自分の操作を録画してレシピ化する」機能を追加します [6]。
* ユーザーが「録画開始」を押してkintoneを操作する。
* 拡張機能がクリックした要素のDOM情報を記録し、自動的にレシピ（JSON）を生成する。
* これにより、ユーザーはプロンプトを書くことなく、自社専用の案内レシピを作成・共有できるようになります。

## 5. 段階的ロードマップ

| フェーズ | 期間 | 主要な開発・ビジネス目標 |
|---|---|---|
| **Phase 1: 基盤強化** | 1〜2ヶ月 | ・Gemini Flash / DeepSeekへのモデル移行<br>・DOM圧縮とセレクタキャッシュの実装<br>・「セカンドカーソル」UIのプロトタイプ開発 |
| **Phase 2: ピボット検証** | 2〜3ヶ月 | ・kintone / Lステップ等の特定ツール向けレシピ作成<br>・「Guide me（案内モード）」の実装<br>・ターゲット層へのテスト営業とフィードバック収集 |
| **Phase 3: スケール準備** | 3〜6ヶ月 | ・ユーザー自身による「レシピ録画・作成機能」のリリース<br>・チーム内でのレシピ共有機能（SaaS課金ポイント）<br>・正式リリースとマーケティング展開 |

## 6. 結論

Quickstart Copilotは、現在の「DOMベースのChrome拡張」という技術的優位性を活かしつつ、ターゲットを「BtoBツールの非ITユーザー」へピボットすることで、巨大な市場機会を掴むことができます。

高額なLLMやVisionモデルに依存せず、**「DOM圧縮＋キャッシュ」で徹底的にコストを下げ**、**「セカンドカーソル」で最高のUXを提供する**。これが、スモールビジネスとして確実に利益を出しながらスケールするための最適解です。

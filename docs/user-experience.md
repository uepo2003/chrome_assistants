# Quickstart Copilot — ユーザー体験ガイド

> 「面倒なセットアップ」「教えるのが大変な操作」を、画面の上で **隣に座ったメンターが手を取って案内してくれる** ような体験に変える Chrome 拡張機能です。

このドキュメントは「何ができるか」を **ユーザーが画面で見るもの・感じるもの・実際にどう使うか** という体験ベースで整理したものです。機能のスペックは [`README.md`](../README.md) と [`docs/product-overview.md`](./product-overview.md) を参照してください。

---

## 一言でいうと

**「次にここを押します／なぜなら〜」と話しかけながら、ブラウザの面倒な操作を隣で代行してくれるセカンドカーソル。**

- BtoB SaaS（kintone / Lステップ / Chatwork / Slack）の操作を、新人や非 IT メンバーに教える代わりにやってくれる
- バイブコーディング系（GitHub / Supabase / Vercel / Cursor / Lovable / API キー発行）の初期セットアップを、つまずきポイントごと案内してくれる
- 「自動化」ではなく「ガイド付き代行」。**主導権はいつでもユーザーに戻せる**

## こんな人の、こんな瞬間に効く

### ペルソナ A：kintone を新人に教える現場リーダー（田中さん）

**Before（拡張なし）**

> 新人 4 人に「kintone のアプリを開いて、新しいレコードを追加して」と説明するために、毎週 30 分 × 4 回。スクショ付きマニュアルを送っても「画面が違います」と Slack DM が飛んでくる。

**After（Quickstart Copilot あり）**

1. 田中さんが新人に「Quickstart Copilot を入れて、カタログから *kintone レコード作成* を選んで」とだけ伝える
2. 新人は kintone を開き、サイドパネルの **「実行する」** をクリック
3. 画面の上にスッと現れたセカンドカーソルが「**次にこの『＋』ボタンを押します（理由：新規レコード作成画面に進むため）**」と説明しながらゆっくり動く
4. 入力欄でいったん停止し「ここに案件名を入れてください」と促される。新人は自分のペースで入力
5. 保存後、「✅ レコードが作成されました」と完了通知

田中さんは Slack DM をゼロにできる。新人は **「教わった」のではなく「一度やった」** 感覚を持って終われる。

### ペルソナ B：Lステップを納品された顧客（佐藤さん）

**Before**

> 代行業者から納品されたシナリオを少し直したいだけなのに、ログインからどこをクリックすればいいか分からず、毎回業者にチャット問い合わせ。

**After**

1. サイドパネルで「Lステップ シナリオ確認」レシピを実行
2. ログイン画面で **「ここはあなたが入力します」と一時停止**（拡張機能はパスワードを触らない）
3. ログイン後はカーソルが左サイドバー → シナリオ一覧 → 該当シナリオ → ステップ編集まで順番にナビゲート
4. メッセージ本文の編集欄で「ここを編集できます」と説明があり、**主導権は佐藤さんに戻る**
5. 保存ボタンも「保存します（理由：変更を反映するため）」と確認しながらクリック

「業者に問い合わせるほどではないけど自信もない」という心理的ハードルが消える。

---

### ペルソナ C：Lovable で作ったアプリを GitHub に繋ぎたい開発初心者（リカさん）

**Before**

> Lovable でアプリは作れた。でも「GitHub と連携してください」「SSH キーを登録」「Vercel に Deploy」がチュートリアル 3 本ぶんあって、もう寝たい。

**After**

1. カタログから **「GitHub アカウント作成」→「SSH キーを追加」→「Lovable と GitHub を接続」→「Vercel に初デプロイ」** をレシピ単位で順に選んで実行
2. それぞれのレシピが、つまずきポイント（メール認証、OAuth ポップアップ、「このキーは一度しか表示されません」画面）で **自動的に止まり、何をすべきか教えてくれる**
3. 認証コードをコピーするタイミングや、ターミナルにコマンドを貼り付けるタイミングも全部「次はこれ」と提示される
4. 30 分後、Vercel の URL がブラウザで開いている

「自動化されすぎて何が起きたか分からない」のではなく **「自分でやった、ただし迷わなかった」** 感覚で終われる。

## 画面ごとの体験

### 1. ツールバーアイコン（ポップアップ）

ツールバーの **QC** バッジをクリックすると小さなポップアップが開く。
そこにあるのはほぼ 1 つだけ：**「Open Sidepanel →」** という大きなボタン。

- 同時にステータスピル（idle / running / paused / error）と **モード**（Rules only / Hybrid / AI only）・**スピード**（Slow / Normal / Fast）・**言語**（EN / 日本語）の切替がコンパクトに並ぶ
- API キー未設定なら、ここで **「API キーを設定してください」** という警告と設定画面へのショートカットが代わりに出る

> 体験のポイント：**ポップアップは「玄関」**。重い操作はここでさせず、サイドパネルへの導線に集中。

### 2. サイドパネル（ホーム画面 = レシピカタログ）

右側に常駐する細いパネル。最初に開いたとき、ユーザーは縦に並んだ **レシピのカード一覧** を見る。

- 一番上に **BtoB ツール（kintone / Chatwork / Slack / Lステップ）** が固定表示
- その下に開発セットアップ系（GitHub / Supabase / Vercel / Cursor / Lovable / Anthropic / OpenAI）
- 検索バー、難易度フィルタ、カテゴリピル
- 各カードには **タイトル・対象サービス・難易度・所要時間・「人間の介入が必要なポイント」** が事前に書いてある（実行前にネタバレされる）
- 健康チェック（対象ホストの到達性）に失敗したカードは自動的にグレーアウト

> 体験のポイント：**「ガチャを引く」のではなく「メニューから選ぶ」**。何が起きるか実行前に分かる。

### 3. レシピ詳細 → 「実行する」

カードをクリックすると、そのレシピが **何をするか／何はしないか（`willTouch` / `willNotTouch`）** が並ぶ。

- たとえば Slack なら：「✅ サイドバーの「+」を触ります」「❌ 既存チャンネルのメッセージは触りません」「❌ 課金設定は触りません」
- 「実行する」ボタンの隣に **「Quick skip（スキップ）」** もある
- 想定ステップ数とトークン推定量（API コスト感）まで開示

> 体験のポイント：**契約書を読んでから契約するように、実行前に「やる/やらない」を確認できる**。

### 4. 実行中：セカンドカーソルとライブ進捗

「実行する」を押した瞬間、画面に **半透明のセカンドカーソル** が現れる。これが Quickstart Copilot の中核体験。

毎ステップ、こう振る舞う：

1. ターゲット要素にスーッと移動
2. その上に小さなラベルを表示：**「次はここをクリック（理由：新規ダイアログを開くため）」**
3. 200〜600ms（スピード設定で可変）滞留 ← **「視線が追いつく時間」を物理的に保証する**
4. クリック / 入力を実行
5. サイドパネルにステップが緑チェックで増えていく

同時にサイドパネルでは：

- 現在のステップ番号と進捗バー
- ステータスピル（`running` で青、`paused` で黄、`complete` で緑、`error` で赤）
- 右上の **赤いストップボタン** でいつでも中断可能
- `prefers-reduced-motion` の環境では、アニメーション（パルス・グライド）は止まるが滞留時間は維持される

> 体験のポイント：**「画面を乗っ取られた感」がない**。Auto モードでも例外なくラベルが出るので、ユーザーは常に「いま何をしているか」が見える。

### 5. 一時停止：人間に主導権が戻る瞬間

レシピは **人間が必ずやるべきこと** を事前に宣言している。OAuth ポップアップ、メール認証、CAPTCHA、「このキーは一度しか表示されません」画面など。

そこに到達すると：

- セカンドカーソルが止まる
- サイドパネルが **黄色の「あなたの番です」カード** に切り替わる
- 何をすべきか・なぜここで止めたかが日英の文章で表示される（例：「Cybozu アカウントでログインしてください。拡張機能はパスワードを扱いません」）
- ユーザーが操作を終えたら **「再開」ボタン** で続きが走り出す

> 体験のポイント：**「全部やってくれる」ふりをしない**。手動が必要な箇所を最初から正直に開示する。

### 6. 完了：終わり方も短く気持ちよく

成功条件（URL パターン or 画面に出るテキスト）を満たすと：

- ステータスピルが緑の `complete` に
- 「✅ 完了しました」とサイドパネルが祝う
- そのレシピが **ローカルの実行履歴（直近 20 件）** に追加される

履歴は後から開いて、何をしたか辿れる。

### 7. 困ったとき：「対応外」も気持ちよく

`chrome://`、Chrome Web Store、OAuth サブウィンドウ、クロスオリジン iframe、closed Shadow DOM——拡張機能が触れない場所はある。

そういうページに対してレシピを実行しようとすると：

- 「このページでは動かせません（理由：〜）」という **日本語/英語のフレンドリーなエラー**
- 自動的に **カタログ画面に戻される**
- 「実行中のまま固まる」UI ハング状態は出ない

## 安心感を作っている 5 つの仕掛け

| 仕掛け | ユーザーの感じ方 |
|---|---|
| **必ずラベル付き滞留** | 「何が起きているか分かる」「今のうちに止められる」 |
| **事前のレシピ宣言（willTouch/willNotTouch）** | 「危ないことはしないと約束されている」 |
| **手動箇所の明示と一時停止** | 「自動なのに、信用しているところと任せないところが分かれている」 |
| **ストップボタン常時表示** | 「いつでも降りられる」 |
| **ローカル完結のプライバシー** | 「クラウドに筒抜けではない」（API キー・録画・履歴・設定すべて `chrome.storage.local`） |

## はじめての 3 分間（オンボーディング）

インストール直後、サイドパネルが自動で開いて 3 ステップのウィザードが走る。

1. **言語を選ぶ** — 日本語 / English
2. **Gemini API キーを登録** — Google AI Studio の無料枠で 0 円スタート可。スキップしても **Guide モード** でデモ体験はできる
3. **最初のレシピを 1 つ選ぶ** — そのままカタログに着地して即実行

> 体験のポイント：**「設定を全部終えてからじゃないと触れない」を撤廃**。Gemini を選ぶ → キーを貼る → 1 つ実行、までを 3 分以内に通す動線。

## カタログにないことをやりたい

### A. オープンエンドモード

カタログ下部に **「自由にゴールを書く」** モードがある。「Notion で新しい DB を作って、テンプレートを 3 つ追加して」みたいな自由文を渡すと、AI が DOM を解析して操作してくれる。

> ただし精度はレシピより落ちる。**v1 のおすすめは「レシピを優先、無い時だけ自由文」**。

### B. レシピ録画（DIY）

カタログ下部の **「自分のレシピを録画する」** から、自分の操作を録画して **Recipe JSON** をエクスポートできる。

- ツールバーアイコンに赤い **REC バッジ** が出ている間だけ記録される（オプトイン徹底）
- パスワード・クレジットカード・OTP・電話番号などの **機微入力は自動的に録画スキップ**
- 完了するとクリップボードコピー & `recipes/_user/<id>.js` 形式でダウンロード
- **ローカル完結**。録画データはクラウドに送られない

> 体験のポイント：kintone や Lステップは **組織ごとに画面が違う**。標準レシピが合わないとき、自社専用版を 5 分で作って配れる。

## 設定で「自分仕様」にする

| 設定 | できる体験のチューニング |
|---|---|
| **AI プロバイダー** | Gemini（既定・無料枠で 0 円スタート）/ DeepSeek / Anthropic / OpenAI |
| **モード** | `Rules only`（API コスト 0、確実な決め打ちレシピのみ）/ `Hybrid`（推奨）/ `AI only` |
| **スピード** | Slow（じっくり見せる）/ Normal / Fast（カーソル滞留 200ms 下限） |
| **言語** | EN / 日本語（カタログ・エラー・ウィザードまで即時切替） |
| **ページ読み込み時の自動起動** | 「チュートリアルっぽいページ」を開いた瞬間、自動で待機する |
| **フォールバック** | プライマリのプロバイダーがエラーになったら自動で別社にリトライ |

## 「ビフォー / アフター」サマリ

### 教える側（現場リーダー、業者、先輩エンジニア）

- Before：同じ十数ステップを毎回口頭・チャット・スクショ付きマニュアルで説明
- After：「カタログから選んで実行してください」で済む / 録画して自社版を渡せる

### 教わる側（新人、非 IT 担当、初学者）

- Before：マニュアルを読みながら自信がなく「これ押していいんですか？」と都度確認
- After：画面の上で「次はここ（理由：〜）」と隣で言ってくれる人がいる感覚

### つまずく開発者

- Before：GitHub / Supabase / Vercel のチュートリアルを 3 本同時に開いて行ったり来たり
- After：レシピを順番に選ぶだけで、認証・キー発行・接続・デプロイが終わっている

## 制限とトレードオフ（正直に）

- **Chromium 系のみ**（Chrome / Edge）。Firefox 未対応
- **クロスオリジン iframe / closed Shadow DOM** の中の要素は触れない
- BtoB ツールは **組織カスタマイズの差分**で標準レシピが合わないことがある → 録画機能で吸収
- AI ステップは **API トークンを消費**する（Rules only / Guide モードなら 0 円）
- 録画レシピのチーム共有はまだ手動 JSON 受け渡し（v1）。共有機能は Phase 4 予定

## 次に試すなら

1. 拡張機能を読み込む（[`README.md` の Install](../README.md#install-dev) 手順）
2. ウィザードで **Gemini** キーを貼る（[AI Studio で無料取得](https://aistudio.google.com/app/apikey)）
3. カタログ先頭の **「kintone レコード作成」** か **「Slack でチャンネル作成」** を 1 件まわしてみる
4. 自分の業務画面と合わなければ、カタログ下部の **「自分のレシピを録画する」** で 1 本作って配ってみる

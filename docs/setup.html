Setup Guide · Quickstart Copilot · v0.3.0

開発環境で試す手順

未署名の拡張機能としてChromeに読み込み、APIキーを入れて、Recipe カタログから 1 件走らせるまでの最短ルートです。 所要時間およそ 5〜10 分。

0前提 1読み込み 2APIキー 3動作確認 4DevTools 5Console 6編集→反映 7トラブル
Step 0

前提を満たす

Side Panel API を使うので Chrome 114以上 が必要です。APIキーは事前に発行しておきます（クレジット設定が必要）。

  • Chrome 114以上（chrome://version で確認）
  • Anthropic コンソールでAPIキー発行（console.anthropic.com）— sk-ant-…
  • クレジット残高が少しある（Haikuなら数円〜数十円で動作確認できます）
  • ローカルにこのリポジトリがある
Step 1

拡張機能をChromeに読み込む

Chromeで chrome://extensions を開く

新しいタブのアドレスバーに直接貼り付けて移動。

右上の「デベロッパーモード」をオンにする

トグルスイッチが緑になれば成功。読み込み用のボタン群が表示されます。

「パッケージ化されていない拡張機能を読み込む」を選択

フォルダ選択ダイアログで auto-tutorial-extension/ を指定。

拡張カードが表示されたら成功

ツールバーの右側にある拡張アイコン → ピン留めしておくと以降の操作が楽です。

chrome://extensions

⚠ アイコン読み込みエラーが出たら icons/icon16.png 等が存在するか確認してください（Pillow生成済みなので通常はOK）。
Step 2

Anthropic APIキーを設定する

オプションページを開く

ツールバーの拡張アイコン → ポップアップ下部の Settings ⚙。
または chrome://extensions → この拡張の 詳細 → 拡張機能のオプション。

「Anthropic API key」にキーを貼り付け → Save

キーは chrome.storage.local にのみ保存されます。ネットワークに出るのは API リクエストヘッダのみ。

「Test connection」で疎通確認

緑の「OK」が出れば成功。失敗時は次の状態を確認：

  • http_401 → キー誤り
  • http_429 → レート制限／クレジット枠不足
  • Network error → オフライン or プロキシ問題

(任意) Mode / Speed / Model を調整

初期値（Hybrid / Normal / claude-haiku-4-5-20251001）でまず動かしてOKです。

Step 3

2つのモードで動作確認

モードA: Quick skip（オンボーディング自動突破）

チュートリアル画面のあるサイトを開く

新規アカウント作成直後のNotion / Linear / Figma などが分かりやすい。

拡張アイコン → 「Quick skip onboarding」

赤い疑似カーソルが現れ、Next / Got it / OK 系を自動でクリックして進めます。

停止は同じボタンの「Stop」

または30回／連続6回ノーオペの安全装置で自動停止します。

モードB: Copilot（ゴール駆動）

任意のサイト（例：github.com）を開く

ログイン状態であることが前提（拡張機能はあなたのセッションを利用します）。

拡張アイコン → 「Open Copilot →」

Chromeの右側に Side Panel が開きます。

テキストエリアにゴール文を入力 → Send

例：「GitHubでdemo-appという名前のプライベートリポジトリを作って」

✓ Run complete

プランカードを確認して Approve

高リスクステップは赤い左ボーダーで強調されます。「Approve」で実行開始。

進行中、必要に応じて返答／承認

  • 値を聞かれたら入力（例：説明文、リポジトリ名）
  • 不可逆操作は承認カードで止まります — Approve / Skip step
  • いつでも上部の Stop で中断可能
💡 まず安全に試すなら Quick skip は本物のサイトで気軽に試せます。Copilotモードは最初は低リスクなゴール（「GitHubのIssue一覧を絞り込んで」「Notionで新しい空ページを作って」等）から始めると挙動が掴みやすいです。
Step 4

DevTools の開き方（5箇所）

拡張機能は複数のコンテキストで動くので、ログ／ブレークポイントを置く場所もそれぞれです。

Service Worker

background/ の挙動を見る

ルーティング、Claude呼び出し、プラン生成のログはここ。

chrome://extensions → この拡張カードの 「サービスワーカー」 リンク
Content Script

ページ上で動くスクリプト

DOMアナライザ・ルール判定・アクション実行のログとデバッグ。

対象タブで F12 → Console。__AT__ が見えれば注入済み。
Side Panel

チャットUI側

メッセージ受信・状態遷移・レンダーの確認。

Side Panel上で 右クリック → 検証
Popup

ツールバーの小さなパネル

Open Copilotボタンや Quick skip のロジック。

ポップアップを開いた状態で 右クリック → 検証
Storage

APIキー・モード・速度の保存先

値が本当に書かれているか・読まれているかの確認。

上のいずれかのDevTools → Application タブ → Storage → Extension Storage
Network

Claude API への通信

送ったプロンプトと返ってきたJSONを直接見られる。

Service Worker の DevTools → Network → api.anthropic.com でフィルタ
Step 5

Console で内部状態を覗く

対象タブのDevToolsコンソールで実行するとデバッグが捗ります。 

// コンテンツスクリプトが注入されているか
globalThis.__AT__
// → { cursor, dom, action, rules, main, speedKey, rulePolicy, debug? }

// 現在の動作状態
__AT__.main.isRunning()
__AT__.main.runMode()       // 'quick-skip' | 'step' | null
__AT__.main.currentStep()   // copilot実行中ならステップ情報
__AT__.main.pendingAskCount()

// 詳細ログを有効化（この後の動作が console.debug に出る）
__AT__.debug = true

// DOMスナップショットを手元で見る
const snap = __AT__.dom.snapshot()
console.table(snap.interactives.slice(0, 10))

// 疑似カーソルを単体で試す
__AT__.cursor.mount(); __AT__.cursor.show()
__AT__.cursor.moveTo(400, 300, 800).then(() => __AT__.cursor.pulseClick())
__AT__.cursor.setLabel("Hello")

// 手動でクイックスキップを発火（権限はpopup経由なので通常はpopupから）
__AT__.main._start()
__AT__.main._stop()
Step 6

ファイル編集→Chrome反映のループ

コードを書き換えたあとは、必ず以下の順で反映してください。順番を間違えると古いコードが残ります。

拡張機能をリロード

chrome://extensions を開き、この拡張カードの 🔄 リロードアイコン をクリック。

対象タブも再読み込み

コンテンツスクリプトは「拡張ロード時にすでに開いていたタブ」には自動再注入されません。Cmd+R でタブを更新します。

Side Panel を開いていれば一度閉じて開き直す

状態をクリーンにするため。

💡 ショートカット chrome://extensions/ をブックマーク or 別タブ常駐にしておくと、編集の往復が高速化します。リロード後にDevToolsを再オープンする必要がある場合も多いので注意。
Step 7

よくあるはまり所

症状原因と対処
UIOpen Copilot を押してもパネルが出ない Chrome 114未満の可能性。chrome://version で確認し、古ければ Chrome を更新。あるいは別ウィンドウで開いた直後はタイミング差で失敗することがあるので、もう一度押す。
APIAI応答が来ない / 「No action」と表示される Service Worker DevTools の Network タブで api.anthropic.com へのリクエストを確認。 http_401 → キー誤り、http_429 → レート/クレジット枠不足、parse_error → モデル応答がJSONになっていない（モデルを変えるか再試行）。
DOMカーソルは動くが本物のクリックが効かない サイトが Shadow DOM の中にUIを置いている可能性。コンソールで __AT__.debug = true を有効化し、dispatch: unresolved target ログを確認。現状はトップフレームのみ対象（manifest all_frames:false）。
DOMiframe内のUIに反応しない 仕様。manifest.json の "all_frames": true に変更すれば各iframeにも注入されますが、副作用（複数カーソル等）あり。慎重に。
URLchrome://系ページで動かない Chrome 内部ページには拡張機能を注入できない仕様。普通の Web ページで試してください（chrome-extension:// / edge:// / about: / view-source: も同様）。
SYNC編集したのに挙動が変わらない 拡張のリロード忘れ。chrome://extensions の 🔄 を押して、さらに対象タブも再読み込み。
MSGCould not establish connection. Receiving end does not exist. コンテンツスクリプトが入っていないタブにメッセージを送った。タブを再読み込みして注入し直す。chrome:// 系ではこのエラーが必ず出ます。
SWService Worker が「停止中」と表示される 仕様：MV3のSWはアイドル時に停止します。何かメッセージを送れば自動的に再起動するので問題なし。停止中にデバッグログが見えなくなるだけ。
COSTAPIコストが心配 Haiku 4.5 の既定設定でプラン生成1回＋ステップあたり1〜3回の呼び出し。1セッション数円〜十数円程度。Console の Network で実際のトークン数を確認可能。Anthropicコンソールで Usage limits を設定推奨。

誰と誰が、どう話しているか

拡張機能は4つの登場人物で成り立っています。あなたが Start を押した瞬間から、メッセージが下のように流れ、ループが回り始めます。

登場人物 1

あなた

ツールバーのアイコンから Start / Stop。モードや速度もここから切り替え。

登場人物 2

ポップアップUI

状態表示と Start/Stop ボタン。API キー未設定なら警告に切り替わる。

登場人物 3

バックグラウンドSW

ポップアップとタブの仲介役。Claude API もここから呼び出す。

登場人物 4

コンテンツスクリプト

実際にページを触る本体。DOMを読み、カーソルを動かし、クリックを発火。

構成要素

5つの部品が役割分担している

ひとつのファイルに詰め込まず、責務を分離しているのでデバッグも差し替えも簡単です。

①

疑似カーソル

content/cursor.js + content.css

22px の赤いドットを画面上に描画。本物のマウスは動かさず、視覚効果として滑らかに移動・クリック演出を行う。

  • ease-out cubic で目線が追える速度
  • クリック時にリップル＋ラベル表示
  • pointer-events:none で実操作を邪魔しない
②

DOMアナライザ

content/dom-analyzer.js

現在の画面から「クリックできる要素」を最大40個まで抽出し、ID付きの一覧（スナップショット）にする。

  • オーバーレイ／チュートリアルクラスを優先
  • 「Next」「OK」「Skip」のテキストを上位に
  • 非表示・画面外の要素は除外
③

ルール判定器

content/rules.js

ローカルで瞬時に判断できるパターンを最初に試す。AI呼び出しを減らしてレイテンシとコストを抑える。

  • 「進行ボタンが1つだけ」→ そのままクリック
  • オーバーレイが消えた → done
  • 曖昧なときは null を返して AI に委譲
④

AIクライアント

background/ai-client.js + prompts.js

ルールで決まらない場面だけ Claude に問い合わせ、次のアクションを1つだけ JSON で返してもらう。

  • 送信するのは要素ラベルの要約（軽量）
  • 応答は厳格にバリデーション
  • 破壊的操作（削除・課金確定）は拒否する設計
⑤

アクション実行器

content/action-executor.js

カーソルを目標まで動かしてから本物のクリック／タイピング／スクロールを発火する。

  • mousedown → mouseup → click を順に
  • React 等の入力リスナにも対応する value setter
  • 画面外ならスムーズスクロールしてから操作
⑥

オーケストレータ

content/main.js

上記5つを束ねるループ。設定の読み取り、ルール／AIの呼び分け、停止条件の監視まですべて担当。

  • ルール ＞ AI のハイブリッド方針
  • 停止信号で in-flight を安全に中断
  • 30周回上限・連続6回ノーオペで自動停止
動作の流れ

Startを押してから、終わるまで

1サイクルあたり 0.5〜1.5秒。これを終了条件に当たるまで繰り返します。

1

popupあなたが Start を押す

ポップアップは現在のタブIDと一緒に AT_START をバックグラウンドへ送信。状態を「Running」に更新（楽観的UI）。

2

backgroundバックグラウンドがタブに転送

chrome.tabs.sendMessage(tabId, ...) でそのタブのコンテンツスクリプトへ。バックグラウンドは「このタブは Running」とメモする。

3

content設定を読み込み、カーソルを表示

chrome.storage から mode と speed を読む → __AT__.cursor.mount() ＋ .show()。ループの周回開始。

4

content画面をスナップショット

DOMアナライザが可視で操作可能な要素を最大40個抽出し、それぞれに ID を割り振る。オーバーレイの有無も判定。

5

rulesルール判定でショートカット

進行ボタンが明らかなら即決定（AI呼び出しなし）。曖昧なら null を返して次へ。Rules-only モードならここで終わり。

6

claudeHybrid / AI モードなら Claude に問い合わせ

スナップショットを軽量テキストに整形してバックグラウンド経由で api.anthropic.com に POST。返答は {"action":"click","targetId":"e3", ...} の単一JSON。

7

contentアクションを正規化して実行

ルールの {kind,id} と AIの {action,targetId} を内部形 {verb,targetId,...} に変換。

8

cursorカーソルを動かして本物のクリック

対象要素の中心へ ease-out で移動 → リップル演出 → mousedown / mouseup / click を順次発火。タイピングなら value setter で React/Vue にも届くイベントを送る。

9

content少し待って次の周回へ

betweenMs + settleMs（speed設定に応じて 350ms〜1.7s）待機してから 4 に戻る。

10

content終了条件で停止

action が done / 30周上限 / 連続6回ノーオペ / ユーザーが Stop、のいずれかでループ終了。カーソルを片付け、ポップアップに STATE_CHANGED を通知。

判断のしくみ

ルールとAIを使い分けるハイブリッド方式

「次へボタンが明らかにそれと分かる」ような単純な場面は、毎回 AI に聞くと遅くてお金がかかります。 最初にローカルのルールで試し、決め手がないときだけ Claude を呼ぶ──これが Hybrid（既定）の挙動です。

ルール判定（高速・無料）

content/rules.js
  • オーバーレイ内に「Next / OK / Continue / Got it」のような 進行系ボタンが1つだけあれば即クリック
  • 進行系がなく、Skip 等の 離脱系ボタン しかない場合はポリシーで判断（既定は離脱しない）
  • オーバーレイ／チュートリアルクラスが完全に消えたら done を返してループ終了
  • 曖昧なケースは null を返して AI に委ねる（保守的）

AI判定（柔軟・有料）

background/ai-client.js + prompts.js → Claude
  • 送るのは URL / タイトル / 可視ボタンのラベル一覧のみ（〜3KB に切り詰め）
  • 応答は単一アクション JSON のみを許可：click / type / scroll / done / skip
  • targetId は スナップショットに実在する ID か を必ず検証
  • 「アカウント削除」など破壊的操作は done で打ち切るようプロンプトで指示
// Claude が返す JSON はこの形だけ受理する
{
  "action": "click",            // click | type | scroll | done | skip
  "targetId": "e3",             // snapshot.interactives[].id を参照
  "text": null,                // type のときだけ文字列
  "deltaY": null,              // scroll のときだけ数値
  "reason": "single primary CTA in onboarding modal"
}
セーフティ

暴走を防ぐ4つの装置

自動で画面を操作する以上、止まらないと困ります。複数の停止条件を重ねて事故を防いでいます。

30最大ループ回数

1セッションで最大30アクションまで。それ以上は強制終了して人手に戻す。

6連続ノーオペ上限

クリック対象が見つからない／実行できない状態が6連続したら自動停止。

⏹ユーザー停止

Stop ボタンで即座に in-flight を打ち切り。カーソルも片付ける。

✋破壊的操作の拒否

「削除」「支払う」「公開する」のような不可逆操作はプロンプトで拒否、done 終了。

前提と制限

送るものと、できないこと

送信しているもの

  • ページの URL とタイトル
  • 可視ボタン／入力欄の ラベル（最大40件、合計約3KBに切り詰め）
  • あなたの Anthropic API キー（リクエストヘッダのみ）

送信していないもの

  • スクリーンショット・画像
  • 入力欄に入っている値
  • ページ本文・記事の中身
  • Cookie・セッショントークン

現状の制限

  • トップフレームのみ（all_frames:false）。iframe内の UI は触れない
  • Shadow DOM は貫通しない（Web Components 製モーダルは対象外）
  • サイトごとに UI 構造が違うため、AI判定の精度はサイト依存
  • Claude を使う以上、利用には Anthropic API のトークン課金が発生
  • chrome:// / chrome-extension:// / about: などの内部ページでは動作不可
Copilot モード

ゴールを伝える → AIが手順化 → 承認後に実行

自動化を「全部おまかせ」にすると怖いし、「全部手動」だと面倒。Copilotモードはその中間です。 ゴール文 → AIがプラン化 → あなたが承認 → 実行 → 迷ったらあなたに質問 → 不可逆操作の前にあなたに承認を求める。

Side Panel に常駐するチャット

拡張アイコンから Open Copilot → を押すと、Chromeの右側にチャットパネルが開きます。 ここで自然文のゴールを入力。 Claudeがプランを3〜7ステップに分解、リスク（low / medium / high）を付けて表示。 Approve を押すと実行開始。

実行中はステップごとに進捗ナレーション。値が必要なら "What name?" と聞いてくるし、 公開・送信・削除のような不可逆操作は 必ず 承認カードでブロック。

フロー（10ステップ）

1

popup"Open Copilot →" をクリック

ポップアップから chrome.sidePanel.open({tabId})（フォールバックで AT_OPEN_PANEL）。サイドパネルが開く。

2

sidepanelゴール文を入力 → AT_GOAL_SUBMIT

サイドパネル → バックグラウンドへ。サイドパネル状態：planning。

3

claudeプラン生成（planner.js）

Claude が JSON 配列で 1〜8ステップ返す。各ステップに {id, title, description, risk, expectedOutcome}。

4

backgroundAT_PLAN_READY をサイドパネルへ

サイドパネルにプランカードが表示され、承認待ち。高リスクステップは赤の左ボーダーで強調。

5

sidepanelApprove → AT_PLAN_APPROVED

承認後、バックグラウンドはコンテンツに AT_STEP_START を 1ステップずつ送出。

6

contentステップ内ループ（最大12回）

スナップショット → ルール／AIで次のアクション決定 → 実行。1ステップ完了で AT_STEP_DONE。

7

claude不明な値があれば ask_user

"プロジェクト名は？" のような質問が必要なときは AI が ask_user アクションを返す。サイドパネルにテキスト入力カードが出てユーザー回答を待つ。

8

guardsリスク評価 → 必要なら confirm

ローカルガード（送信・削除・支払い・公開のキーワード検出）と AI 自身の判断を組み合わせ、不可逆な操作は 必ず 承認カードを出す。

9

cursor承認後、疑似カーソルで実行

Side Panel に「Clicking 'Create repository'…」と実況。本物のクリックを発火。

10

content全ステップ完了 → AT_RUN_COMPLETE

カーソル片付け、Side Panel にサマリ表示。AT_USER_STOP はいつでも割り込み可。

競合との違い

Perplexity Comet / ChatGPT Operator / Manus との差別化

AIにブラウザを操作させるプロダクトは他にもありますが、ほとんどが「別ブラウザ」か「クラウドVM上の別セッション」で動きます。 この拡張機能は あなたが今ログインしているChromeそのもの で動くこと、そして 明示的な承認ゲート を入れていることが大きな違いです。
